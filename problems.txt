# 21. The exact bug your Antigravity prompt should address

Your current system appears to be doing something like:

```text
Retrieve chunks
       ↓
LLM generates answer
       ↓
LLM generates "missing fields"
       ↓
LLM generates risk factors
       ↓
LLM generates checklist
```

That's why you get contradictions like:

> **Structured Key Facts: Interest Rate = 10.50%**

while simultaneously:

> **Document Review: Interest Rate = NOT_SPECIFIED**

That should be **impossible** in a robust architecture.

You need:

```text
                    DOCUMENT
                       ↓
              STRUCTURED FACT STORE
                       ↓
             ┌─────────┴─────────┐
             ↓                   ↓
       User Scenario        Document Review
             ↓                   ↓
             └─────────┬─────────┘
                       ↓
                 RULE ENGINE
                       ↓
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
     Missing        Conflicts       Risks
        ↓              ↓              ↓
        └──────────────┼──────────────┘
                       ↓
                 CALCULATOR
                       ↓
                  LLM ANSWER
                       ↓
                CLAIM VERIFIER
                       ↓
               FINAL VALIDATOR
```

**The missing-information detector should NEVER ask the LLM "is APR present?"**

It should query your structured fact store:

```python
facts["apr"]
```

If no verified APR fact exists:

```text
NOT_SPECIFIED
```

That's deterministic.

## Most important fixes to make now

I would tell Antigravity to prioritize these **before adding more prompts**:

1. **Separate document facts from user scenario.**
2. **Create a canonical loan-field schema.**
3. **Map synonyms:** `prepayment = early repayment = foreclosure = pre-closure`.

The most serious problem right now isn't that the LLM's wording is imperfect. **It's that different parts of your RAG are producing mutually contradictory views of the same document.** Fixing that data/validation architecture will improve the system far more than adding another giant system prompt.
